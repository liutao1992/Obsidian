# PostgreSQL B-Tree 索引

## 适用场景

B-tree 可以处理能够按某种顺序排序的数据上的**等值查询**和**范围查询**。

## 支持的操作符

当索引列涉及使用以下运算符之一进行比较时，PostgreSQL 查询规划器都会考虑使用 B-tree 索引：

- `<`
- `<=`
- `=`
- `>=`
- `>`

## 支持的等价结构

等价于上述运算符组合的结构也可以通过 B-tree 索引搜索来实现：

- `BETWEEN`
- `IN`

此外，索引列上的 `IS NULL` 或 `IS NOT NULL` 条件也可以使用 B-tree 索引。

## 模式匹配支持

如果模式（pattern）是一个**常量且锚定在字符串的开头**，优化器还可以将 B-tree 索引用于涉及模式匹配运算符的查询：

| 运算符    | 示例                | 是否支持  |
| ------ | ----------------- | ----- |
| `LIKE` | `col LIKE 'foo%'` | ✅ 支持  |
| `~`    | `col ~ '^foo'`    | ✅ 支持  |
| `LIKE` | `col LIKE '%bar'` | ❌ 不支持 |

> **注意**：如果数据库未使用 **C 区域设置（locale）**，则需要使用特殊的**运算符类（operator class）**来创建索引，以支持模式匹配查询的索引化。


### 正则表达式用法详解

`col ~ '^foo'` 是 PostgreSQL 中的正则表达式匹配：

| 部分 | 含义 |
|------|------|
| `~` | 正则表达式匹配操作符（区分大小写） |
| `^` | 锚定字符串**开头** |
| `foo` | 要匹配的具体字符 |

**示例**：

```sql
SELECT * FROM users WHERE name ~ '^foo';
-- 匹配: 'foo', 'foobar', 'foo123'
-- 不匹配: 'afoo', 'barfoo', 'FOO' (区分大小写)
```

**相关操作符对比**：

| 操作符 | 含义 | 示例 |
|--------|------|------|
| `~` | 正则匹配（区分大小写） | `col ~ '^foo'` |
| `~*` | 正则匹配（不区分大小写） | `col ~* '^foo'` 匹配 `Foo`、`FOO` |
| `!~` | 正则不匹配（区分大小写） | `col !~ '^foo'` |
| `!~*` | 正则不匹配（不区分大小写） | `col !~* '^foo'` |

## 排序优化

B-tree 索引还可以用于**按排序顺序检索数据**。这并不总是比简单的扫描加排序更快，但通常是很有帮助的。
